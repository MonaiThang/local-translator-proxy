# Translation Proxy v1 Specification

This document is the implementable v1 spec for the Translation Proxy. It records decisions from the [wayfinder map](https://github.com/MonaiThang/local-translator-proxy/issues/1). The game call site must remain unchanged (ADR-0002). The proxy listens on `127.0.0.1:5000` only.

## 1. Game-facing contract (inbound)

- **Method**: `GET` (verb not validated)
- **URL**: `http://127.0.0.1:5000/` (any path accepted; only query string parsed)
- **Query parameters**:
  - `text` (string, required): percent-encoded UTF-8 of the Translation Unit
  - `from` (string, optional): source language, default `zh-CN`
  - `to` (string, optional): target language, default `en`
- **Encoding**: Percent-encoded UTF-8. `+` decodes to a space and `%2B` stays `+` (matching the game's original .NET parser). Malformed `%` sequences are left as-is; parsing never returns `400`.
- **Placeholders**: literal `{text}` or whitespace-only → return original unchanged with `200 OK`
- **Granularity**: Split on `(\r\n|\r|\n)`. Translate each **non-blank line separately**. Reinsert separators verbatim.

**Response (success/passthrough):**
- `200 OK`
- `Content-Type: text/plain; charset=utf-8`
- Body: raw UTF-8 bytes of the result

**Response (failure):** Prefer `200 OK` with original Translation Unit (Passthrough Response) per ADR-0003. Avoid stalling the game.

## 2. Parsing, validation, and language pairs

- **Normalization**: lowercase `from`/`to` for comparison; accept BCP47-like tags (e.g. `zh-CN`, `en`, `ja`); no aliases in v1.
- **Supported pairs**: fixed allowlist in config. Unsupported pairing → **Passthrough Response**.
- **Invalid/missing/empty**: missing `text`, unparseable query, empty after decoding → **Passthrough Response**.
- **Unknown params**: ignored.

## 3. Rendering Tokens and line breaks

- **Separators**: real `\r\n`, `\r`, `\n` are line separators (split/rejoin). Not "tokens" for cross-translation verification except they must be preserved.
- **Tokens (v1 minimal set)**: XML/HTML-like tags commonly used by UGUI/TextMeshPro: `<color=...>`, `</color>`, `<size=...>`, `</size>`, `<b>`, `</b>`, `<i>`, `</i>`, `<u>`, `</u>`, `<s>`, `</s>`, `<sprite name=...>`, `<quad ...>`, `<br>`, `<br/>`. Literal `\n`/`\r\n` inside text (escaped) treated as tokens to preserve if present.
- **Verification**: extract tokens in order from original and translated result (per Translation Unit/line as appropriate). **Positional match required** (same tokens, same order, same count). If extraction ambiguous or mismatch → **Passthrough Response** for entire Translation Unit.
- **Model compliance**: proxy enforces verification regardless of model behavior.

## 4. Model Runtime integration

- **Transport**: non-streaming `POST` to configurable endpoint, default `http://127.0.0.1:11434/api/chat`
- **Request body**: `{ "model": "...", "messages": [...], "stream": false, "options": {"temperature": 0, "seed": <fixed>} }`
- **Prompt**:
  - **System message**: the configured `prompt.system_message`, with `Source language: <from>` and `Target language: <to>` appended on their own lines. The configured text is otherwise sent verbatim. The shipped default states the exact `{"translation": "..."}` schema and requires JSON escaping of quotes and backslashes so literal `\n` / `\r\n` tokens survive the round-trip.
  - **User message**: one physical non-blank line, verbatim (tokens and escaped line breaks intact)
- **Output**: structured JSON with a single field `translation` (e.g. `{"translation": "..."}`) to avoid preambles/quoting. Two response envelopes are accepted:
  - the body itself is `{"translation": "..."}`, or
  - an Ollama-style `message.content` string containing `{"translation": "..."}`.
  - Extra fields in the structured payload are rejected.
  - One surrounding Markdown code fence (`` ``` `` or `` ```json ``) around the `message.content` payload is tolerated; prose outside the fence is not.
- **Failures** (flat set → Passthrough): connection refused/unreachable, non-2xx, timeout, unparseable/schema-violating response, missing/empty `translation`, token mismatch, an injected real line break in a translated line
- **Timeout**: `timeout_secs` is a wall-clock deadline for the **whole Translation Unit** (permit waits, all model calls, and verification), not a per-call timeout. Default `5s`, configurable.
- **Concurrency**: lines are forwarded concurrently with a small in-flight cap (default `4`); the cap applies to Model Runtime calls across the unit.

## 5. Configuration

TOML file + environment variable overrides. No CLI flags in v1.

```toml
[server]
listen_addr = "127.0.0.1:5000"

[model_runtime]
endpoint = "http://127.0.0.1:11434/api/chat"
model = "gemma2:9b"  # example; user must have model installed
timeout_secs = 5
max_in_flight = 4
seed = 12345

[languages]
supported_pairs = [["zh-CN", "en"]]  # fixed allowlist
default_from = "zh-CN"
default_to = "en"

[prompt]
system_message = "..."  # must state the JSON schema and enforce token preservation
```

Env overrides use explicit single-underscore names (not a nested separator): `TRANSLATOR_PROXY_SERVER_LISTEN_ADDR`, `TRANSLATOR_PROXY_MODEL_RUNTIME_ENDPOINT`, `TRANSLATOR_PROXY_MODEL_RUNTIME_MODEL`, `TRANSLATOR_PROXY_MODEL_RUNTIME_TIMEOUT_SECS`, `TRANSLATOR_PROXY_MODEL_RUNTIME_MAX_IN_FLIGHT`, `TRANSLATOR_PROXY_MODEL_RUNTIME_SEED`, `TRANSLATOR_PROXY_LANGUAGES_SUPPORTED_PAIRS`, `TRANSLATOR_PROXY_LANGUAGES_DEFAULT_FROM`, `TRANSLATOR_PROXY_LANGUAGES_DEFAULT_TO`, `TRANSLATOR_PROXY_PROMPT_SYSTEM_MESSAGE`.

## 6. Implementation notes

- **Language**: Rust (ADR-0001)
- **No SDK**: use plain HTTP client
- **Reference target**: Ollama `/api/chat` (runtime-agnostic spec)
- **Out of scope**: choosing/installing Model Runtime, changing game call, Translation Corpus/eval, versioned/non-loopback API, full implementation (this is spec only)
- **Fixtures**: see `docs/fixtures/game-request-sample.md`, research in `docs/research/`
- **Open unknowns**: exact game text samples with real Rendering Tokens may require adjustment of the minimal token set
